# Growth Engine — MVP ($0 budget, fully deployed)

This is the complete build from the original plan — SEO audit, on-demand content
generation, and an automatic weekly content-gap scanner — running at **$0/month**,
no credit card used anywhere.

## What's live right now
- **Backend**: FastAPI Cloud — free Hobby plan
- **Database + login**: Supabase — free tier
- **Frontend**: Vercel — free tier
- **AI**: Groq — free tier, no credit card
- **Weekly auto-generator**: a free external cron service triggers it (see below) —
  replaces the paid Celery/Redis worker most guides assume you need

## What's actually working
- **Content generator** (`backend/routers/content_gen.py`) — blog posts, landing
  page copy, text ads, video scripts, generated by Groq from a simple form
- **Login/signup** (`frontend/pages/login.js`) via Supabase — generated content
  saves to your account automatically once logged in
- **Google Search Console integration** — real OAuth flow
  (`backend/routers/google_auth.py`), pulls actual ranking/click data, feeds it to
  the AI for an audit (`/audit/search-console-report`)
- **Meta (Instagram/Facebook) OAuth**, fully coded (`backend/routers/meta_auth.py`)
  — works for your own account added as a "Tester"; real users need Meta's App
  Review first (their process, not something buildable in code)
- **LinkedIn OAuth**, fully coded (`backend/routers/linkedin_auth.py`) — identity
  login works with no review; real post/engagement data needs LinkedIn's Marketing
  Developer Platform approval
- **Module 2 — the auto-generator, free version** (`backend/core/tasks.py` +
  `backend/routers/internal.py`) — scans each connected user's Search Console data,
  asks the AI to flag underperforming pages, and auto-drafts a blog post per gap
  into `content_drafts` with `source='auto'`. Triggered weekly by a free external
  cron job hitting `POST /internal/run-weekly-scan` — see "Free weekly auto-scan
  setup" below
- **Auto-Suggested Content Feed** (`frontend/pages/feed.js`,
  `backend/routers/feed.py`) — lists pending auto-drafts with Approve/Dismiss
- **WordPress publishing** (`backend/core/wordpress_client.py`) — approving a blog
  draft pushes it to a connected WordPress site as a draft post (no app review
  needed, just an Application Password from WP admin)
- **Tests** (`backend/tests/test_core.py`) and **CI** (`.github/workflows/ci.yml`)

## What's genuinely not possible to finish in code
- **Meta/LinkedIn real user data**: needs their platform review process — an
  external approval only you can request, on their timeline
- **Auto-publishing** for landing pages/ads/video scripts: no universal "publish"
  target the way a blog maps to WordPress, so those stay copy-paste
- **X (Twitter) and SerpAPI/DataForSEO**: not wired up — same OAuth/API-key pattern
  as the others would apply if you want to add them later

## Free weekly auto-scan setup (replaces paid Celery/Redis)

Instead of a paid background worker running on a schedule, a free cron service
calls your backend once a week to run the same scan.

1. **Set a secret** so random visitors can't trigger it: in your backend terminal,
   ```
   fastapi cloud env set --secret INTERNAL_SCAN_SECRET
   ```
   (paste any random string when prompted, then `fastapi deploy`)

2. **Sign up at cron-job.org** (free, no card) → Create cronjob
   - URL: `https://bilaye.fastapicloud.dev/internal/run-weekly-scan`
     (swap in your actual FastAPI Cloud URL)
   - Method: `POST`
   - Schedule: weekly, whatever day/time you like
   - Under "Advanced" → Headers: add `X-Scan-Secret` with the same value you set
     in step 1

3. That's it — it'll run weekly for free, dropping auto-drafted content into each
   connected user's Feed page.

To test it immediately instead of waiting a week, send a POST request with that
header yourself (Postman, curl, or even cron-job.org's "Run now" button once set up).

## Getting your API keys from zero

**1. Groq (required, free)** — console.groq.com/keys → Create API Key →
`GROQ_API_KEY`

**2. Supabase (required, free)** — supabase.com → New project → Settings → API →
copy **Project URL** and **service_role** key into backend, **Project URL** +
**anon public** key into frontend. Run `supabase/schema.sql` in the SQL Editor.

**3. Google Search Console OAuth (free, no review needed)** —
console.cloud.google.com → new project → enable "Google Search Console API" →
OAuth consent screen (External, add yourself as a test user) → Credentials →
OAuth client ID (Web application) → redirect URI must exactly match
`GOOGLE_OAUTH_REDIRECT_URI` → copy Client ID/Secret. The Google account you
connect must already have the target site verified in Search Console.

**4. Meta (optional, free until you need real users)** —
developers.facebook.com/apps → Create App (Business) → add "Instagram Graph API"
→ add yourself as a Tester under Roles → copy App ID/Secret. Submit for App
Review later when ready for real customers.

## Deploying (how this was actually deployed)

**Backend → FastAPI Cloud**
```bash
cd backend
pip install "fastapi[standard]"
fastapi login
fastapi deploy
```
No credit card required. Add secrets with `fastapi cloud env set --secret KEY_NAME`
(prompts for the value, or `fastapi cloud env set KEY_NAME value` to set it inline).
Redeploy with `fastapi deploy` after adding/changing env vars.

**Frontend → Vercel**
Import the repo at vercel.com, set **Root Directory** to `frontend`, add
`NEXT_PUBLIC_BACKEND_URL` (your FastAPI Cloud URL) and the Supabase vars, deploy.
Then set `FRONTEND_URL` on the backend to your Vercel URL — `backend/main.py`
reads it to allow CORS from your live frontend automatically.

## Environment variables

**`backend/.env`**
| Variable | Required? | What it's for |
|---|---|---|
| `GROQ_API_KEY` | ✅ Yes | Powers all content generation — free, console.groq.com/keys |
| `GROQ_MODEL` | Optional | Defaults to `llama-3.3-70b-versatile` |
| `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | ✅ Yes | From your Supabase project settings |
| `FRONTEND_URL` | ✅ Yes | Your live Vercel URL, for CORS |
| `INTERNAL_SCAN_SECRET` | For Module 2 | Any random string; must match your cron job's header |
| `GOOGLE_SEARCH_CONSOLE_CLIENT_ID` / `_SECRET` | For Search Console | Google Cloud Console → OAuth credentials |
| `GOOGLE_OAUTH_REDIRECT_URI` | For Search Console | Must exactly match what's registered in Google Cloud |
| `META_APP_ID` / `META_APP_SECRET` | For Meta | Meta for Developers dashboard |
| `LINKEDIN_CLIENT_ID` / `_SECRET` | For LinkedIn | LinkedIn Developer Portal |
| `WORDPRESS_URL` / `_USERNAME` / `_APP_PASSWORD` | Optional | For auto-publishing blog drafts |

**`frontend/.env.local`**
| Variable | Required? | What it's for |
|---|---|---|
| `NEXT_PUBLIC_BACKEND_URL` | ✅ Yes | Your FastAPI Cloud URL |
| `NEXT_PUBLIC_SUPABASE_URL` / `_ANON_KEY` | ✅ Yes | From Supabase project settings →  API  |
